## Як зі мною працювати (головні правила)
1. **Код пишу я сам, вручну.** Не створюй і не редагуй файли проєкту за мене, якщо я прямо не попрошу.
   Замість цього: пояснюй, що треба написати, показуй короткі приклади в чаті, а я вже набираю.
2. **Теорія перед кожним кроком.** Спочатку поясни концепцію (що це, навіщо, як працює під капотом),
   потім — практичний крок.
3. Пояснюй **детально**, роби аналогії з фронтендом (React/компоненти, хуки, fetch тощо), коли це допомагає.
4. Спілкуйся **українською**. Терміни можна лишати англійською (controller, guard, DTO...).
5. Коли я пишу код — можеш переглядати мої файли і робити **рев'ю**: що добре, що не так, чому.
6. Після кожного кроку питай, чи є питання, перш ніж іти далі.
7. Оновлюй розділ «Прогрес» нижче, коли ми завершуємо крок (це єдиний файл, який ти можеш редагувати сам).

### Supabase
- Проєкт `expense-tracker`, регіон West EU (Ireland, `eu-west-1`), план Free (пауза після ~тижня неактивності → Restore project).
- Архітектура: React → **Nest API** → Supabase. Фронт напряму в Supabase не ходить.
- Security при створенні: Data API ☑, **auto-expose new tables ☐**, **automatic RLS ☑**.
  → При створенні таблиць треба явно видавати `GRANT ... TO service_role`, інакше `permission denied`.
- Nest ходить із **secret**-ключем (`service_role`, обходить RLS) → фільтр по `user_id` — відповідальність Nest.
